# 当前功能优化计划（Feature Optimization Plan）

> 更新时间：2026-09-01
>
> 范围：针对当前已经实现的功能做“可用性、效率、治理、性能、体验”的优化计划。
> 目标不是补基础功能，而是把现有能力打磨成更像产品的交付体验。

## 1. 优化原则

1. **先主路径，后边角**：优先优化“登录 → 建知识 → 对话 → 评测 → 发布 → 回滚”。
2. **先减少理解成本，后增加配置自由度**：默认模板和引导要比复杂参数更重要。
3. **先可解释，后自动化**：每一次失败、限流、回滚都要让用户知道原因。
4. **先统一交互，再做局部创新**：减少页面风格和交互割裂。
5. **先可观测，再可优化**：没有指标就不要大改策略。

## 2. 现有功能优化总表

| 模块 | 当前状态 | 主要问题 | 优化方向 | 优先级 |
|---|---|---|---|---|
| 登录 / 身份 | 已有 JWT / OIDC 钩子 / 用户管理基础 | 首次使用仍有理解成本 | 首次登录向导、邀请用户、角色模板、SSO 配置助手（详见 [Onboarding Wizard 优化方案](./onboarding-wizard-optimization-plan.md)） | P0 |
| 租户 / 权限 | RBAC 已存在 | 权限边界对普通管理员不够友好 | 权限说明、角色模板、资源级提示、越权错误可读化 | P0 |
| 对话 / Run | 有会话、流式、引用、重试 | 结果对比和回放还不够“分析型” | 会话搜索、Run Compare、引用聚合、失败定位卡片 | P0 |
| 知识库 | 能入库、检索、引用 | 上传后“是否生效”反馈不足 | 索引状态、chunk 预览、召回调参、增量更新、去重提示 | P0 |
| 评测 | 有基准 / 回归 / 安全评测 | 评测结果呈现偏工程化 | Dataset 管理、版本对比、趋势图、评测模板、标注闭环 | P0 |
| 发布 | 契约 / 回归 / 灰度 / 回滚已具备 | 流程信息量大，学习成本高 | 发布向导、门禁摘要、差异对比、失败原因聚合 | P0 |
| 成本 | 有用量聚合 | 只看总量不够，难以优化 | 按模型/工具/Agent 分解、预算告警、异常波动、月报 | P1 |
| 工具 / MCP | 工具治理有基础 | 工具接入与排障较重 | 工具测试台、权限说明、Secret 引用可视化、市场化目录 | P1 |
| 审计 / 事件 / 队列 | 基础齐全 | 搜索、关联、导出体验一般 | 全文搜索、关联 Run/Release、DLQ 一键处理 | P1 |
| 配置中心 | 已有版本化配置 | 对用户“配置生效”的反馈不直观 | 变更 diff、发布预览、回滚提示、影响范围分析 | P1 |
| 前端体验 | 组件覆盖较全 | 一致性、加载态、空态仍不统一 | 统一页面骨架、状态文案、按钮 loading、错误贴近操作区 | P0 |
| 性能 | 已做部分拆包 | 大页面仍可继续优化 | 表格虚拟化、缓存、预取、接口批量化 | P1 |

## 3. 按用户主路径的优化清单

### 3.1 路径 A：首次进入平台

**目标**：把“第一次成功”变快。

> 详细拆解见：[Onboarding Wizard 优化方案](./onboarding-wizard-optimization-plan.md)。

| 问题 | 现象 | 优化方案 | 验收标准 |
|---|---|---|---|
| 不知道先做什么 | 用户打开后会先看一堆菜单 | 增加 onboarding wizard 和主路径 CTA | 首次进入能明确下一步 |
| 默认配置太多 | 用户不确定什么能改 | 提供默认模板和推荐值 | 80% 用户无需看文档即可开跑 |
| 登录后空白感强 | 需要自己找页面 | 首页加入“下一步建议” | 首页能指引到具体操作 |

### 3.2 路径 B：导入知识并验证效果

**目标**：让用户快速确认“知识真的生效”。

| 问题 | 现象 | 优化方案 | 验收标准 |
|---|---|---|---|
| 上传后缺少反馈 | 不知道文档有没有索引成功 | 显示 ingestion 状态、失败原因、耗时 | 用户能看懂状态 |
| 检索结果不透明 | 只看到答案，没看到为什么命中 | 增加命中 chunk、分数、引用链 | 能解释答案来源 |
| 调参成本高 | 不清楚 top_k / rerank / chunk 的影响 | 增加检索调优面板和预设 | 非研发也能做基础调优 |

### 3.3 路径 C：Run / 对话排障

**目标**：让排障从“看日志”变成“看图就能定位”。

| 问题 | 现象 | 优化方案 | 验收标准 |
|---|---|---|---|
| 失败原因过散 | 时间线、消息、工具、trace 分散 | 统一失败摘要卡片 | 一眼看到失败原因 |
| 对比成本高 | 无法快速比较两次 run | 提供 Compare 视图 | 能看出参数和输出差异 |
| 缺少搜索 | 会话多了之后难找 | 增加会话 / Run 搜索和过滤 | 能按关键字段快速定位 |

### 3.4 路径 D：发布与回滚

**目标**：让发布从“专业操作”变成“有引导的安全流程”。

| 问题 | 现象 | 优化方案 | 验收标准 |
|---|---|---|---|
| 信息密度高 | 契约、回归、灰度、版本很多 | 发布向导分步展示 | 用户知道当前卡在哪一步 |
| 门禁不够解释化 | 失败后只知道没过 | 门禁结果增加“原因 + 建议动作” | 能直接指导修复 |
| 回滚决策不直观 | 看到指标但不容易判断 | 增加“当前版本 vs 上一版本”对比 | 可以快速决定是否回滚 |

## 4. 按功能模块的优化计划

### 4.1 Dashboard / 首页

**现状**：已有总览，但更偏数据汇总。

**优化项**：

- 加入“待办任务”区域：待发布、待审批、失败 run、告警、配额告警
- 加入“最近一次成功路径”快捷入口
- 加入环比变化解释：为什么成本涨了、为什么队列高了
- 对管理员与普通用户展示不同首页内容

**建议优先级**：P0

---

### 4.2 Chat / Run

**现状**：已有会话持久化、流式、停止、重试、引用来源。

> 交互与视觉层面的详细拆解见：[聊天框 UI 优化计划](./chat-ui-optimization-plan.md)。

**优化项**：

- 支持会话搜索、置顶、收藏、归档
- 支持 Run Compare：prompt / model / tools / retrieval / output diff
- 增加“失败摘要”和“一键重试上次配置”
- 引用来源支持聚合视图：同一文档多次命中可折叠
- 增加用户反馈：有用 / 无用 / 需人工处理
- 增加分享能力：生成只读链接或导出报告

**建议优先级**：P0

---

### 4.3 Knowledge

**现状**：已有上传、入库、检索、引用。

**优化项**：

- 显示索引状态：排队 / 处理中 / 成功 / 失败
- 增加 chunk 预览与回溯
- 支持文档去重、版本更新、覆盖策略说明
- 增加检索调参页：top_k、rerank 开关、分块策略预设
- 增加“问答命中率”与“召回质量”反馈

**建议优先级**：P0

---

### 4.4 Evaluation

**现状**：有评测页，但更像工程面板。

**优化项**：

- Dataset 管理：新增、克隆、归档、版本化
- 评测模板：客服问答、知识问答、工具调用、安全问题
- 结果趋势：按版本、模型、prompt、知识版本对比
- 标注闭环：人工修正错例后直接回流 dataset
- 评测门禁建议：通过 / 警告 / 阻断三档可解释

**建议优先级**：P0

---

### 4.5 Release

> 详细拆解见：[发布页面优化方案](./release-page-optimization-plan.md)。

**现状**：流程完整，但复杂度较高。

**优化项**：

- 发布向导（见 [发布页面优化方案](./release-page-optimization-plan.md)）：概览、差异、门禁、灰度、回滚五步
- 发布摘要：本次改了什么、影响什么、风险在哪
- Canary 结果图：错误率、延迟、成本、工具成功率、RAG Recall
- 一键回到上一个稳定版本
- 发布历史支持对比和复盘导出

**建议优先级**：P0

---

### 4.6 Cost

**现状**：已有聚合，但更偏后台数据。

**优化项**：

- 按租户 / 用户 / Agent / 版本 / 模型 / 工具拆分
- 预算接近阈值时主动提醒
- 增加成本异常检测：突然上涨、长尾会话、超大上下文
- 提供月度账单摘要和导出
- 提供“优化建议”：哪个模型贵、哪个工具慢、哪个知识库命中率差

**建议优先级**：P1

---

### 4.7 Tools / MCP / Secrets

**现状**：工具治理已存在，但对接和排障成本仍高。

**优化项**：

- 工具测试台：输入参数、看返回、看审批、看审计
- Secret 引用可视化：用户能知道用了哪个凭据，但看不到明文
- 工具权限说明：每个工具为什么需要权限、为什么要审批
- 工具目录 / 连接器目录：按场景筛选，而不是只按技术名
- 高风险工具的风险提示更明确

**建议优先级**：P1

---

### 4.8 Audit / Queue / Events

**现状**：有基础能力，但偏运维侧。

**优化项**：

- 审计记录按对象关联：用户、租户、Run、Release、Tool
- 支持审计检索与导出模板
- 队列页面增加优先级、积压原因、预计恢复时间
- Dead Letter 一键重放前先展示失败原因
- 事件流支持按 dedupe_key / trace_id / resource 搜索

**建议优先级**：P1

---

### 4.9 Config Center

**现状**：已经版本化，但用户感知不强。

**优化项**：

- 配置 diff 视图
- 发布前预览“哪些用户会受影响”
- 回滚时解释回滚到哪个版本、会恢复什么
- Feature Flag 规则可视化

**建议优先级**：P1

---

## 5. 前端统一体验规范

### 5.1 必做规范

1. 所有异步按钮必须有 loading 和防重复提交。
2. 成功 / 失败提示必须贴近触发动作。
3. 写操作成功后必须刷新列表或详情。
4. 删除 / 回滚 / 停用必须二次确认。
5. 空态必须给出下一步行动。
6. 筛选 / 分页联动必须回到第一页。
7. 表单校验必须贴近字段，不能只在提交后报总错。

### 5.2 建议补齐的 UI 一致性

- 页面级 Skeleton 覆盖所有长表格页
- 统一 EmptyState / ErrorState / PermissionDenied
- Run / Release / Knowledge 的状态标签统一颜色与文案
- 详情页的侧边操作区统一“主操作 / 次操作 / 危险操作”排序

## 6. 性能与稳定性优化

### 6.1 前端性能

| 问题 | 优化动作 | 预期收益 |
|---|---|---|
| 大表格渲染重 | 虚拟滚动 / 分页缓存 | 列表页更流畅 |
| 页面切换慢 | 预取常用路由 chunk | 降低切换等待 |
| 首次加载仍重 | 继续拆分公共依赖 | 提升首屏速度 |
| 刷新抖动 | 统一 splash / skeleton | 提升感知体验 |

### 6.2 后端性能

| 问题 | 优化动作 | 预期收益 |
|---|---|---|
| 列表查询分散 | 统一分页与过滤索引 | 降低数据库压力 |
| 评测/检索重复计算 | 加强缓存与失效策略 | 降低推理和检索开销 |
| 事件/审计量增长 | 分区、归档、保留期清理 | 降低长期存储压力 |
| 并发 run 峰值 | 进一步优化队列与限流 | 稳定高峰体验 |

## 8. 优化完成后的判断标准

如果优化完成，用户应该能在以下问题上得到更好的答案：

1. **我现在该做什么？** —— 首页和 onboarding 告诉他。
2. **为什么这个答案可信？** —— Run / Knowledge / Trace 告诉他。
3. **为什么这次发布更好？** —— Eval / Release 告诉他。
4. **为什么成本变高了？** —— Cost / Model / Tool 告诉他。
5. **出了问题怎么恢复？** —— Audit / Queue / Backup / Rollback 告诉他。

这就是当前功能优化的最终目标。
